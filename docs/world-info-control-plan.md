# 世界书发送控制方案

## 目标

在聊天输入区实时显示下一次生成预计会触发的世界书条目、实际发送文本、token 数量和发送位置，并允许用户临时决定哪些条目可以进入提示词。

临时排除只作用于当前页面会话中的当前聊天及后续生成，不修改世界书文件，也不改变条目原本的启用状态。用户可以随时重新纳入条目或清空全部临时排除。

本功能作为“酒馆工具箱”的独立模块实现，不并入聊天文件管理模块。

## 结论

该功能可以只用前端扩展实现，不需要服务端插件，也不需要修改 SillyTavern 源码。

推荐使用三条酒馆原生链路：

1. 使用 `checkWorldInfo(..., true)` 对当前聊天与输入草稿执行世界书干跑扫描，得到发送前的预计触发条目
2. 使用扩展清单的 `generate_interceptor` 在每轮生成进入世界书扫描前锁定本轮临时排除快照
3. 监听 `WORLDINFO_ENTRIES_LOADED`，从本轮扫描使用的条目副本中移除临时排除项
4. 复用酒馆的宏替换、世界书正则、位置拼接和 tokenizer，生成面板使用的发送文本、位置顺序与 token 数据

酒馆在读取世界书缓存时会返回结构化副本，随后才发送 `WORLDINFO_ENTRIES_LOADED` 并进入匹配、概率、分组、递归和预算处理。因此修改事件参数不会写回缓存或世界书文件，而且排除发生在完整扫描之前，不会让被排除条目继续参与递归或分组计算。

## 原生链路依据

本方案基于 SillyTavern `release` 分支提交 `51ad27fb86d39a3daca3adaa970375c9670c12df`：

- `public/script.js` 先运行扩展生成拦截器，再构造 `chatForWI` 并调用 `getWorldInfoPrompt`
- `public/scripts/extensions.js` 的 `runGenerationInterceptors` 会按扩展加载顺序等待每个拦截器完成
- `public/scripts/world-info.js` 的 `getSortedEntries` 先加载全局、角色、聊天和用户世界书条目，再发送 `WORLDINFO_ENTRIES_LOADED`
- `public/scripts/world-info.js` 的 `checkWorldInfo` 在条目载入之后执行启用检查、关键词匹配、概率、分组、递归、预算和位置处理
- `WORLDINFO_SCAN_DONE` 提供实际扫描状态，可用于生成后校准面板，但不作为本轮排除入口

酒馆助手的提示词查看器通过虚假生成请求取得接近最终发送状态的完整提示词。该思路适合手动查看完整提示词，但完整生成装配包含预设、正则、宏和其他插件处理，不适合在每次输入变化时重复执行。本模块只需要世界书结果，因此采用范围更小的原生世界书干跑扫描，并保留“手动刷新时重新扫描”的操作。

## 交互设计

### 入口

在聊天输入区附近增加一个紧凑入口，显示世界书图标和预计触发数量，例如“世界书 6”。没有选中角色或群聊时入口禁用，并说明当前没有可扫描的聊天上下文。

入口打开输入区上方的轻量面板，不使用独立全屏管理弹窗，也不混入聊天文件管理面板。

### 面板内容

面板按实际发送位置分组，并按该位置中的最终拼接顺序显示预计触发条目。世界书只作为来源信息，不作为分组或排序依据。

每条显示：

- 条目名称或备注
- 所属世界书
- 处理后的发送文本
- 实际插入位置
- 内容 token
- 当前状态：“发送”或“临时排除”

关键词和条目原文不占用默认列表空间。需要排查触发原因时，可以在条目详情中查看主关键词和次关键词，但正文预览始终显示处理后的发送文本。

条目开关表示是否允许该条目进入生成提示词。它只控制插件的会话覆盖层，不代表世界书中的永久启用开关。

面板提供两个辅助操作：

- 重新扫描
- 清空当前聊天的临时排除

不提供修改世界书、永久停用条目或保存覆盖配置的入口，避免和原生世界书编辑器职责重叠。

### 状态提示

面板使用轻提示区区分以下状态：

- 正在扫描
- 预计触发数量
- 结果已因输入或聊天变化而过期
- 本轮实际触发结果已校准
- 扫描失败，临时排除仍会在正式扫描时应用

发送前列表应标记为“预计触发”，不能宣称它在所有情况下都等于最终结果。概率条目、黏性与冷却、递归条目以及其他插件在生成前修改上下文时，都可能让正式扫描结果发生变化。

## 发送文本、token 与排序

### 发送文本

不能直接使用世界书条目的原始 `content`。酒馆在条目通过匹配和概率检查后会先执行 `substituteParams`，在构建世界书提示词时再执行 `getRegexedString(..., WORLD_INFO)`。聊天补全中的角色前后世界书还会经过当前预设的世界书提示词模板，示例、作者注释、深度注入和 outlet 也各自走对应的原生拼接链路。

面板的数据分为两层：

- 条目发送文本：宏和世界书正则处理后的该条目正文，用于条目开关和逐条查看
- 位置发送块：同一位置的条目按酒馆顺序合并，并应用该位置对应的提示词模板，用于查看真正交给后续提示词装配的文本

默认展开条目发送文本；位置标题可以展开查看完整发送块。原始 `content` 不作为发送预览，只能放在调试详情中与发送文本对照。

正式生成时使用 `WORLDINFO_SCAN_DONE` 和后续生成数据事件校准实际发送块。发送前干跑结果继续标记为“预计”，生成开始后的结果标记为“实际”。

### token

使用酒馆当前 tokenizer 的 `getTokenCountAsync`，不自行引入 tokenizer，也不按字符数估算。

- 条目右侧显示处理后条目发送文本的 token
- 位置标题显示应用模板并完成合并后的发送块 token
- 面板顶部显示全部世界书发送块的内容 token

总数必须从最终发送块分别计算，不能把逐条 token 直接相加。tokenizer 会受相邻文本、分隔符、提示词模板和消息边界影响，逐条数字之和不一定等于合并后的精确数量。面板显示的是世界书内容 token，不包含聊天补全协议为角色和消息增加的隐藏开销。

token 结果按“tokenizer 标识 + 处理后文本”缓存。模型、tokenizer、模板或发送文本变化时自动失效。

### 实际发送位置排序

列表不提供名称、世界书或 token 排序选项，固定跟随实际发送位置。

位置分组覆盖：

- 角色定义前与角色定义后
- 示例消息前与示例消息后
- 作者注释前与作者注释后
- 指定深度，包含深度和角色
- outlet，包含 outlet 名称

同一位置内不另写一套比较器，而是使用酒馆扫描结果生成的最终数组顺序。指定深度按酒馆实际注入深度和角色分组，outlet 按名称分组。不同生成后端无法映射成同一条绝对文本序列时，按原生提示词区块顺序显示，并明确标注位置；实际生成完成后再用最终生成数据校准。

## 状态模型

### 条目标识

使用 `world + uid` 作为条目身份，不使用条目名称、关键词或内容。名称和内容可能被编辑，世界书名与条目 UID 才对应酒馆扫描阶段的实际来源。

### 临时排除

运行时维护：

```text
Map<chatKey, Set<entryKey>>
```

- `chatKey` 区分角色聊天与群聊
- `entryKey` 由世界书名和条目 UID 组成
- 切换聊天后使用对应聊天自己的集合
- 切回原聊天时，在当前页面生命周期内保留之前的临时排除
- 刷新页面、关闭模块或清空操作会移除临时排除
- 不写入 `extension_settings`、聊天元数据或世界书文件

### 本轮快照

生成拦截器在每轮开始时复制当前聊天的排除集合。本轮正式扫描只读取该快照，生成过程中继续操作开关只影响下一轮，避免扫描中途状态变化造成部分条目使用新状态、部分条目使用旧状态。

## 运行链路

### 实时预览

```text
输入、聊天或世界书变化
    -> 标记当前结果过期
    -> 400 ms 防抖
    -> 组装当前聊天、输入草稿和世界书扫描上下文
    -> checkWorldInfo(..., true)
    -> 提取 allActivatedEntries
    -> 执行宏、世界书正则和位置模板处理
    -> 按实际发送位置生成发送块并计算 token
    -> 丢弃过期任务结果
    -> 更新数量与条目列表
```

预览扫描必须包含酒馆当前使用的：

- 聊天消息及输入草稿
- 是否在扫描文本中包含角色名
- 角色描述、角色性格、角色深度提示
- 用户人设描述
- 场景和创作者备注
- 当前最大上下文
- 正常发送对应的触发类型

消息预处理尽量复用酒馆导出的正则与上下文接口，不复制完整生成器。无法可靠读取的待上传附件或第三方临时提示应让结果标记为“预计”，而不是构造假的确定结果。

预览结果不能从原始条目重新猜测模板展开结果。扫描器应保留 `checkWorldInfo` 返回的各位置最终数组，并结合 `allActivatedEntries` 建立条目身份、发送文本和位置发送块之间的映射。

### 正式生成

```text
用户或其他酒馆原生操作发起生成
    -> generate_interceptor 锁定当前聊天与排除快照
    -> 酒馆加载本轮世界书条目副本
    -> WORLDINFO_ENTRIES_LOADED
    -> 插件从四类条目数组中移除快照内条目
    -> 酒馆执行原生匹配、概率、分组、递归和预算处理
    -> WORLDINFO_SCAN_DONE 更新实际触发记录、发送文本和位置顺序
    -> 后续生成数据事件校准模板处理后的实际发送块与 token
    -> 酒馆继续组装提示词并发送
```

需要同时处理 `globalLore`、`characterLore`、`chatLore` 和 `personaLore`，不能只过滤全局世界书。

过滤必须原地修改事件提供的数组，不能调用 `saveWorldInfo`，不能更改 `worldInfoCache`，也不能临时切换原生 `disable` 后再恢复。

### 非普通发送

临时排除作用于所有经过酒馆原生世界书扫描的生成方式，包括普通发送、继续、重试、滑动回复、群聊生成和由其他扩展发起的酒馆生成。

实时草稿预览只对应普通发送。其他触发方式发生时，面板使用 `WORLDINFO_SCAN_DONE` 返回的实际结果刷新，不能拿普通发送预测冒充对应触发类型的结果。

## 性能方案

不在每个按键事件中立即扫描，也不反复执行完整虚假生成。

采用以下限制：

- 输入防抖默认 400 ms，不增加用户设置项
- 同一时间只允许一个预览扫描，后续变化只保留最新请求
- 使用聊天修订号、草稿、世界书修订号和相关设置组成缓存键
- 处理后文本未变化时复用 token 结果，同一批新文本并行计数
- 页面正在生成时暂停输入预览，避免和正式扫描并发
- 角色、群聊或聊天未就绪时不扫描
- 模块关闭时移除所有监听、计时器和运行时状态
- 面板关闭后仍可维护入口计数；如果后续实测大型世界书开销明显，再改为面板打开时扫描，不预先增加性能设置

世界书文件本身由酒馆缓存，主要成本是上下文拼接、关键词匹配、递归和 token 预算计算。相比酒馆助手提示词查看器的完整虚假生成，本方案不会重复装配模型请求、预设和最终提示词。

## 并发与边界

- 输入变化使旧结果失效时，旧扫描可以完成，但不得覆盖新结果
- 点击发送时若预览仍在运行，生成拦截器先锁定排除快照；预览结果只能更新界面，不能改变该轮快照
- 群聊需要以当前聊天为状态范围，不能按当前出场角色拆分排除集合
- 世界书条目删除或 UID 不再存在时，下次扫描清理对应的无效排除项
- 原生永久禁用条目不会出现在预计触发列表中，插件也不提供临时启用永久禁用条目的能力
- 工具箱或模块关闭后，生成拦截器必须退化为立即放行
- 扫描异常不得阻止用户发送；正式生成继续走酒馆原生链路，只记录错误并显示轻提示
- 酒馆事件或数据结构不可用时禁用模块入口，不使用 DOM 猜测或猴子补丁替代
- 提示词模板或其他插件在干跑之后改变发送文本时，面板必须把旧结果标记为过期，并以正式生成捕获结果覆盖

## 目录结构

```text
modules/
  world-info-control/
    definition.js          模块设置定义
    module.js              生命周期与依赖装配
    scanner.js             预览扫描与最新任务收敛
    prompt-view.js         发送文本、位置顺序与 token 视图模型
    overrides.js           聊天级排除状态与正式扫描过滤
    ui.js                  输入区入口和面板交互
templates/
  world-info-control/
    panel.html
    settings.html
styles/
  world-info-control/
    panel.css
```

模块只设置一个“世界书发送控制”总开关。防抖时间、结果缓存、实际结果校准等属于实现细节，不增加无必要的用户配置。

`index.js` 只增加模块定义注册。`manifest.json` 增加固定的生成拦截器名称；模块关闭时该全局函数保留但立即返回，避免动态修改清单或重载扩展。

## 实施顺序

1. 建立独立模块、设置开关和输入区静态面板
2. 完成聊天级临时排除状态与清理边界
3. 接入世界书干跑扫描，显示预计触发条目、发送文本和 token
4. 接入生成拦截器和 `WORLDINFO_ENTRIES_LOADED` 正式过滤
5. 使用 `WORLDINFO_SCAN_DONE` 和生成数据事件校准实际文本、位置、token 与状态提示
6. 补齐角色、群聊、聊天切换、世界书更新和生成类型测试
7. 在大型世界书与长聊天下测量输入扫描耗时，再决定是否需要进一步降频

## 验收条件

- 输入变化后可以看到下一次普通发送预计触发的条目
- 每条默认显示宏、世界书正则处理后的发送文本，而不是原始 `content`
- 使用提示词模板的位置可以查看应用模板后的完整发送块
- 条目、位置发送块和全部世界书均显示对应 token
- 条目按实际发送位置及原生拼接顺序排列
- 临时排除条目后，本轮和后续生成的提示词不包含该条目
- 重新纳入后，下一轮恢复酒馆原生判断
- 世界书编辑器中的条目启用状态和文件内容始终不变
- 全局、角色、聊天和用户世界书均可正确识别与过滤
- 普通发送、继续、重试、滑动和群聊生成均走同一正式过滤链路
- 切换聊天不会串用临时排除状态
- 刷新页面后临时排除自动清空
- 快速输入不会让旧扫描结果覆盖最新结果
- 模块关闭或扫描失败不会阻止酒馆正常生成
