# 提示词查看与世界书控制方案

## 模块边界

功能拆分为两个互不依赖的模块。

### 提示词查看器

提示词查看器只读取真正进入正式发送链路的最终请求：

- 聊天补全监听请求参数完成后的 `CHAT_COMPLETION_SETTINGS_READY`
- 文本补全监听请求数据完成后的 `GENERATE_AFTER_DATA`
- 忽略 `dryRun` 产生的预览
- 按最终消息顺序显示角色、正文和 Token
- 支持搜索、折叠、悬浮气泡和输入区固定入口

查看器不执行虚假生成，不分析来源，也不修改发送内容。切换聊天后清空旧快照，下一次正式生成时写入新快照。捕获和 Token 计算在后台执行，不让正式请求等待查看器。

### 世界书控制

世界书控制只负责本轮会触发的世界书条目：

- 面板打开时调用酒馆原生 `getWorldInfoPrompt`
- 扫描上下文时包含输入框尚未发送的草稿
- 输入变化后仅在面板展开时防抖扫描
- 按世界书分组显示条目、处理后正文、位置、顺序和 Token
- 临时关闭状态按聊天保存在内存中
- 正式生成时在 `WORLDINFO_ENTRIES_LOADED` 阶段过滤关闭项

关闭项不参与关键词匹配、递归、预算计算和最终发送。插件不修改世界书文件及条目的原生启用状态。

## 不实现的控制

发送控制不覆盖以下内容：

- 预设提示词
- 用户人设
- 角色描述、性格和场景
- 聊天上下文消息
- 其他扩展注入

这些内容在最终请求中可能被模板处理、合并或移除来源标识。当前酒馆没有与世界书条目等价的稳定前置过滤接口，因此不提供可能失效或误删内容的开关。

## 运行时状态

世界书排除状态使用：

```text
Map<chatKey, Set<worldName:uid>>
```

- 角色聊天与群聊分别生成 `chatKey`
- 切换聊天时保留当前页面生命周期内各聊天的状态
- 关闭模块或刷新页面后清空
- 切换开关只更新内存状态，不重新扫描列表

## 性能与并发

- 面板关闭时不因输入变化执行扫描
- 面板打开后使用 400ms 防抖
- 同一时刻只运行一个扫描任务
- 扫描期间发生新变化时，在当前任务结束后补做一次最新扫描
- 预览和正式扫描都应用关闭项过滤，避免发送与预览并发时绕过控制
- 正式生成直接复用酒馆的世界书事件，不额外运行第二次扫描

## 目录

```text

  prompt-common/          最终消息快照与 Token 计算
  prompt-viewer/          真实最终提示词捕获和只读面板
  world-info-control/     世界书扫描、排除状态和控制面板
templates/
  prompt-viewer/
  world-info-control/
styles/
  prompt-viewer/
  world-info-control/
```

## 验收边界

- 两个模块拥有独立设置开关和生命周期
- 提示词查看器不触发生成，也不影响真实请求
- 世界书控制能够根据当前上下文和草稿更新触发列表
- 关闭条目后列表不刷新，下一次正式发送不包含该条目
- 重新开启条目后恢复酒馆原生扫描行为
- 任一模块失败都不能阻止酒馆正常发送
