# 提示词查看与世界书控制方案

## 模块边界

功能拆分为两个互不依赖的模块。

### 提示词查看器

提示词查看器读取请求组装完成后、即将发送的提示词：

- 聊天补全监听请求参数完成后的 `CHAT_COMPLETION_SETTINGS_READY`
- 文本补全监听请求数据完成后的 `GENERATE_AFTER_DATA`
- 忽略 `dryRun` 产生的预览
- 按最终消息顺序显示角色、正文和 Token
- 打开面板或点击刷新时主动获取当前提示词
- 支持搜索、折叠、悬浮气泡和输入区固定入口

主动获取复用酒馆的正常提示词组装链路。输入框草稿仅在组装期间加入内存上下文，完成后立即移除并恢复输入框；整个过程不保存或渲染用户消息，并在网络请求发出前中止。查看器不分析来源，也不修改发送内容。切换聊天后清空旧快照；正式生成时同样更新快照。捕获和 Token 计算在后台执行，不让正式请求等待查看器。

### 世界书控制

世界书控制只负责本轮会触发的世界书条目：

- 面板打开时调用酒馆原生 `getWorldInfoPrompt`
- 扫描上下文时包含输入框尚未发送的草稿
- 输入变化后仅在面板展开时防抖扫描
- 按来源和酒馆加载顺序分组显示条目、处理后正文和 Token
- 关闭状态按世界书持久化在工具箱设置中
- 正式生成时在 `WORLDINFO_ENTRIES_LOADED` 阶段过滤关闭项

关闭项不参与关键词匹配、递归、预算计算和最终发送。插件不修改世界书文件及条目的原生启用状态。

## 不实现的控制

发送控制不覆盖以下内容：

- 预设提示词
- 用户人设
- 角色描述、性格和场景
- 聊天上下文消息
- 其他扩展注入

这些内容在最终请求中可能被模板处理、合并或移除来源标识。当前酒馆没有与世界书条目等价的稳定前置过滤接口，因此不提供可能失效或误删内容的开关。

## 运行时状态

世界书排除状态在运行时使用：

```text
Map<worldName, Set<uid>>
```

- 同一本世界书在不同聊天中共用关闭状态
- 切换聊天、关闭模块或刷新页面后仍保留状态
- 设置中以 `Record<worldName, string[]>` 序列化保存
- 切换开关只更新当前列表和持久设置，不重新扫描列表

## 性能与并发

- 面板关闭时不因输入变化执行扫描
- 面板打开后使用 250ms 防抖
- 同一时刻只运行一个预览任务，重复刷新收敛为一次最新扫描
- 预览扫描保留关闭项以判断本轮是否触发，正式生成才应用关闭过滤
- 扫描超过 30 秒会恢复为错误状态，不会永久停留在加载中
- 相同条目正文复用上一轮 Token 结果
- 正式生成直接复用酒馆的世界书事件，不额外运行第二次扫描
- 折叠期间保存正式生成结果，再次展开时由用户动作刷新完整预览

## 验收边界

- 两个模块拥有独立设置开关和生命周期
- 提示词查看器可主动组装提示词，并在网络请求发出前中止
- 世界书控制能够根据当前上下文和草稿更新触发列表
- 关闭条目后列表不刷新，下一次正式发送不包含该条目
- 重新开启条目后恢复酒馆原生扫描行为
- 任一模块失败都不能阻止酒馆正常发送
