# 本轮提示词查看与发送控制方案

## 目标

新增独立的“本轮提示词控制”模块，用于查看下一次生成准备发送给模型的提示词，并临时决定其中哪些内容参与发送。

控制只作用于当前页面会话中的当前聊天及后续生成，不修改预设、世界书、角色卡、聊天消息或其他扩展的原始数据。刷新页面、关闭模块或手动清空后，全部内容恢复由 SillyTavern 原生规则决定。

本模块不属于聊天文件管理。工具箱只负责统一注册、设置和生命周期。

该功能可以只用前端扩展实现，不需要服务端插件，也不修改 SillyTavern 源码。最终提示词由发送前事件取得；来源结构在提示词被扁平化之前捕获；临时控制只修改本轮装配副本或发送事件参数。

## 三种视图

三种视图是三个明确实现，不是同一列表换一个排序名称。

### 1. 本轮提示词

参考酒馆助手提示词查看器的使用方式，显示本轮最终准备发送的提示词：

- 聊天补全按最终消息数组显示角色、内容、Token 和发送顺序
- 文本补全显示最终合并字符串及总 Token
- 展示已经执行的宏、提示词模板、世界书格式、正则和前端扩展处理结果
- 区分“当前预览”和“实际生成”
- 支持搜索、复制和折叠长内容

这是最终请求视图，回答“这轮实际会发什么”。

### 2. 发送位置

按最终发送的提示词消息或文本区段分组。每个顶层节点就是一个实际发送位置，展开后显示构成它的来源项：

- 预设提示词
- 世界书条目
- 角色定义与用户人设
- 示例消息
- 上下文聊天消息
- 作者注释、记忆、向量等扩展注入
- 无法继续拆分的合并内容

顶层节点严格使用最终发送顺序。子项显示来源、处理后文本、Token、发送状态及其在顶层节点中的顺序。

这是结构化发送视图，回答“每个最终消息由什么组成”。

### 3. 来源类型

按内容来源分组：

- 预设
- 世界书
- 角色与人设
- 示例消息
- 上下文消息
- 扩展注入
- 生成控制内容
- 其他或无法识别

每组内部仍按实际发送位置和实际发送顺序排列，不使用名称或 Token 重新排序。切换视图不会重新扫描，也不会改变发送状态。

这是来源审查视图，回答“每类内容向本轮请求贡献了什么”。

## 两种承载方式

### 本插件自带面板

在聊天输入框附近放置固定的折叠入口：

- 收起时只显示一个提示词按钮和本轮 Token
- 点击后在输入区上方展开面板
- 面板内切换“本轮提示词”“发送位置”“来源类型”三种视图
- 再次点击入口或面板收起按钮恢复为单个按钮
- 切换角色、群聊或聊天后复用面板位置，只替换当前聊天数据

不使用独立全屏弹窗，不占用聊天文件管理面板。

### 酒馆助手提示词查看器增强

增加一个可选适配模块。检测到酒馆助手及其提示词查看器可用时，把“发送位置”“来源类型”和临时发送控制接入酒馆助手查看器。

- 不复制、覆盖或修改酒馆助手源码
- 只使用稳定的公开事件或可确认的扩展接口
- 与本插件自带面板共享同一个数据仓库和控制状态
- 两边同时存在时，任一处切换状态都会立即同步
- 酒馆助手缺失、关闭或接口变化时，仅停用适配层，自带面板继续完整工作

适配模块提供的是等同于自带实现的增强能力，不另建一套扫描和过滤链路。如果酒馆助手没有稳定接入点，不使用 DOM 结构猜测或覆盖其内部函数，设置中显示“不兼容当前版本”。

## 统一数据模型

一次扫描只生成一张本轮提示词图，三种视图只是它的不同投影。

```text
PromptSnapshot
  finalNodes[]
    id
    sendIndex
    role
    processedContent
    tokenCount
    contributionIds[]
  contributions[]
    id
    sourceType
    sourceId
    sourceName
    finalNodeId
    orderInNode
    processedContent
    tokenCount
    controlLevel
  exclusions
```

`finalNodes` 对应最终发送消息或文本区段，`contributions` 对应可确认来源的构成项。三种视图必须引用同一 ID 和同一排除集合，不能各自维护开关。

### 可控层级

每个节点明确标记控制能力：

- `source`：能在原生装配前安全排除单个来源项
- `final`：只能在最终请求事件中排除整个消息或区段
- `locked`：协议必需、工具调用链或无法安全排除的内容，只能查看

界面只对真正可控的节点显示发送开关。不能安全拆分的合并内容作为一个整体控制，不通过字符串查找、占位符或正则删除其中一段。

## 发送控制

### 状态范围

运行时维护按聊天隔离的排除集合：

```text
Map<chatKey, Set<controlId>>
```

- 普通角色聊天和群聊使用不同 `chatKey`
- 切回聊天时，在当前页面生命周期内保留之前选择
- 默认影响本轮及该聊天的后续发送
- 用户可逐项重新纳入或一键清空当前聊天排除
- 不写入 `extension_settings`、聊天元数据或来源文件

### 控制规则

- 关闭来源项时，在对应原生装配阶段排除，确保它不再参与后续合并
- 关闭最终节点时，聊天补全从发送数组移除对应消息；文本补全从允许发送的结构化区段重新合成最终字符串
- 父组开关只批量操作组内可控子项，不产生额外永久状态
- 工具调用及其结果必须成组处理，避免破坏请求协议
- 关闭当前最后一条用户消息、继续生成前缀等关键内容时给出明确提示
- 排除后重新计算最终 Token，不能只把子项 Token 相减

预览面板中的开关立即影响下一次发送。一次生成开始时锁定排除快照；生成过程中继续修改只影响下一轮，避免同一轮装配使用两套状态。

## 原生链路与可行性

方案基于 SillyTavern `release` 提交 `51ad27fb86d39a3daca3adaa970375c9670c12df`。

### 聊天补全

`prepareOpenAIMessages` 在装配阶段使用 `Message` 和 `MessageCollection`：

- 预设和系统内容保留 `identifier`
- 上下文消息使用 `chatHistory-*` 标识
- 示例消息、控制提示词和扩展注入各自保留集合或消息标识
- 每个消息对象保存 Token
- `ChatCompletion.getChat()` 输出最终消息数组时会去掉这些内部标识
- 启用“合并系统消息”后，连续系统消息还会在最终事件前被合并

因此来源关系必须在 `ChatCompletion` 的结构化阶段捕获，不能只监听最终数组后再猜测。实际请求仍以 `CHAT_COMPLETION_PROMPT_READY` 的 `data.chat` 为准，并在该事件中应用最终节点排除。

### 文本补全

`GENERATE_BEFORE_COMBINE_PROMPTS` 提供 `finalMesSend`、世界书区块、示例、故事字符串和其他装配字段；随后酒馆把它们合并为字符串，并通过 `GENERATE_AFTER_COMBINE_PROMPTS` 暴露最终 `data.prompt`。

来源图在合并前建立，最终内容和最终节点排除在合并后校准。已经被模板或其他扩展改写成不可分割字符串的内容只能作为整体控制。

### 世界书

世界书条目在 `WORLDINFO_ENTRIES_LOADED` 后进入匹配、概率、分组、递归、预算、宏替换和正则处理。插件使用：

- 干跑扫描生成预计触发项
- `WORLDINFO_ENTRIES_LOADED` 在正式扫描前过滤临时排除条目
- `WORLDINFO_SCAN_DONE` 校准实际激活项、处理后文本和位置

事件中的条目是本轮扫描副本。过滤数组不会保存世界书，也不会改变条目原生启用状态。

### 预设与其他来源

预设、角色、人设、示例和上下文消息必须使用酒馆装配阶段已有的标识建立控制项。第一版只接入能够通过原生对象、事件参数或稳定导出接口排除的来源。

若某个来源只能通过修改全局设置、临时保存原文件、猴子补丁或最终字符串匹配才能关闭，则先标记为只读，不实现伪开关。后续只有找到稳定的前置装配接口后才升级为 `source` 控制。

## 实时预览与正式发送

### 当前预览

参考酒馆助手提示词查看器，在打开面板或刷新时执行一次不请求模型的提示词装配，并捕获结构化来源和最终提示词。

```text
打开面板或相关输入变化
    -> 标记快照过期
    -> 防抖并取消旧任务写回资格
    -> 执行预览装配
    -> 捕获结构化来源图
    -> 捕获最终消息或字符串
    -> 建立三种视图并计算 Token
    -> 更新展开面板及酒馆助手适配层
```

输入变化不应每次都执行完整装配。面板展开时使用短防抖更新；收起时只把快照标记为过期，下一次展开或发送前再刷新。

原生 `Generate(..., dryRun = true)` 不会把输入框里尚未发送的草稿追加成普通用户消息。不得临时修改聊天数组伪造草稿。实现阶段优先复用酒馆助手已经验证的虚假生成链路；若无法通过稳定接口取得包含草稿的预览，就明确标记“预览不含未发送草稿”，实际生成时再校准。

### 正式发送

```text
酒馆开始生成
    -> 锁定当前聊天的排除快照
    -> 在各来源原生装配前应用 source 排除
    -> 酒馆完成宏、模板、世界书和扩展处理
    -> 捕获实际结构化来源和最终请求
    -> 应用 final 排除
    -> 重新计算最终 Token
    -> 更新三种视图为“实际生成”
    -> 放行请求
```

插件不额外增加“确认后才能发送”的强制弹窗。用户在输入区折叠面板中提前控制；正式发送只校准并执行已锁定状态，不改变酒馆原来的发送动作。

如果正式装配与预览不同，界面以实际生成结果覆盖预览，并标记本轮新增、消失或变更的节点。不能在最终事件才关闭一个需要前置重算的来源项；该操作从下一轮生效。

## 处理后文本、排序与 Token

### 处理后文本

默认显示进入本轮请求的处理后文本，不显示来源原文：

- 宏替换后的预设内容
- 宏和世界书正则处理后的世界书内容
- 提示词模板处理后的最终消息
- 其他前端扩展处理后的可见结果

来源原文仅在调试详情中可选查看。处理后失去来源边界时，界面显示“已合并”，不强行归属到某个条目。

### 排序

- 本轮提示词：严格使用最终请求顺序
- 发送位置：顶层按最终请求顺序，子项按在该节点中的装配顺序
- 来源类型：使用固定类型分组，组内按最终请求顺序和节点内顺序

不提供自定义排序，防止显示顺序与真实发送顺序混淆。

### Token

统一使用酒馆当前 tokenizer：

- 显示最终总 Token
- 显示每个最终节点 Token
- 显示可独立计算的来源项 Token
- 分组标题显示当前允许发送项的合计

最终总数必须对应用排除后的完整请求重新计数。多个子项 Token 不能直接相加代替合并结果，因为分隔符、消息边界、模板和 tokenizer 都可能改变总数。

前端无法看到模型服务商或服务端追加的隐藏提示词时，界面标记为“前端发送 Token”，不宣称等于服务商最终计费 Token。

## 设置

本轮提示词控制模块提供：

- 启用本轮提示词控制
- 启用酒馆助手提示词查看器增强

自带折叠面板属于模块基础入口，不另设开关。三种视图、搜索、Token、刷新和折叠属于面板功能，不增加细碎设置。

酒馆助手增强开关仅在检测到兼容版本时可用，并显示当前接入状态。

## 性能与并发

- 面板收起时不随每次输入执行完整预览
- 面板展开时对输入变化防抖，始终只允许最新任务更新界面
- 实际生成直接复用装配事件，不额外执行第二次完整 dry-run
- Token 按 tokenizer 标识和处理后内容缓存
- 模型、预设、世界书、聊天、输入或相关扩展状态变化时使快照过期
- 正在正式生成时暂停后台预览
- 切换聊天后取消旧聊天任务的写回资格
- 模块关闭时移除监听、计时器、适配层 UI 和临时排除状态
- 捕获或增强失败不得阻止酒馆发送

## 边界

- 只控制当前前端可见且有稳定装配边界的内容
- 不修改来源文件和原生永久启用状态
- 不通过 DOM 猜测提示词来源
- 不通过字符串查找删除合并后的单个来源
- 不覆盖酒馆助手函数或依赖其私有 DOM 层级
- 不保证包含服务端再次追加或改写的提示词
- 其他扩展在本插件捕获事件之后修改请求时，面板只能显示本插件捕获时的前端状态
- 不可安全排除的协议消息和工具调用显示为锁定
- 角色、群聊或聊天未就绪时保留入口，但禁用刷新和控制

## 实施顺序

1. 建立统一快照、节点身份和临时排除状态
2. 实现自带折叠入口与“本轮提示词”视图
3. 捕获聊天补全和文本补全的预览及实际请求
4. 建立结构化来源图，实现“发送位置”和“来源类型”视图
5. 接入最终节点发送控制与 Token 重算
6. 接入世界书条目级捕获和前置过滤
7. 逐项验证预设、角色、人设、示例、上下文和扩展注入的安全控制边界
8. 实现酒馆助手提示词查看器增强适配层
9. 补齐角色、群聊、继续、重试、滑动、工具调用和文本补全测试
10. 在长聊天、大型世界书和高频输入下测量装配与渲染耗时

## 验收条件

- 输入框附近始终只有一个可折叠入口，展开后无需弹窗即可查看
- 本轮提示词视图显示本轮前端最终消息或字符串及 Token
- 发送位置视图能从最终节点展开查看来源项
- 来源类型视图按类型分组，组内保持实际发送顺序
- 三种视图共享同一个发送状态，切换视图不丢失选择
- 可控项关闭后不进入下一次请求，重新开启后恢复原生装配
- 临时控制不修改预设、世界书、角色卡、聊天或扩展设置
- 世界书显示宏、正则和模板链路中当前可确认的处理后内容
- 无法安全拆分或排除的内容明确显示为整体或锁定，不提供假开关
- Token 对应用排除后的完整请求重新计算
- 酒馆助手增强与自带面板功能和状态一致
- 未安装或关闭酒馆助手时，自带实现仍可独立工作
- 关闭模块、刷新页面或清空状态后全部临时排除消失
- 捕获、预览或适配失败不会阻止正常发送
